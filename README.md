# WatchUp Backend

WatchUp Backend는 KRW 기반 암호화폐 마켓 검색, 관심 코인 관리, 현재가 조회 및
일봉 차트 제공을 담당하는 FastAPI 서버입니다. 사용자 인증과 데이터 접근 권한은
Supabase Auth/JWKS와 PostgreSQL RLS를 사용하며, Upbit 공개 Quotation API의
응답은 Redis 캐시와 결합해 제공합니다.

모든 공개 JSON 필드는 camelCase를 사용하고, 성공 및 오류 응답은 일관된
envelope 형식으로 반환합니다.

## 주요 기능

- 인증이 필요 없는 애플리케이션 health check
- Supabase JWKS 기반 Bearer JWT 검증
  - ES256 및 RS256 서명 지원
  - 만료 시간, issuer, audience, `sub` 검증
  - 사용자별 Supabase Client와 PostgreSQL RLS 적용
- Upbit KRW 마켓 목록 적재 및 코인 검색
  - 한글명, 영문명, 마켓 코드 검색
  - 대소문자 무시 및 exact → prefix → contains 우선순위
  - 최대 20개 결과 반환
- 사용자별 관심 코인 등록 및 목록 조회
  - 사용자당 최대 50개
  - 사용자와 마켓 코드 조합의 중복 방지
  - 서버가 검증한 코인명만 저장
- 관심 코인 현재가 및 등락률 조회
  - 여러 마켓을 하나의 Upbit ticker 요청으로 조회
  - 일부 마켓의 가격 누락을 `PRICE_ERROR`로 격리
  - fresh/stale 가격 캐시 지원
- 30일 일봉 차트 조회
  - 최대 30개 종가를 날짜 오름차순으로 반환
  - fresh/stale 차트 캐시 지원
- Redis 기반 캐시 및 cache stampede 방지
  - token 소유권을 검증하는 Lua 기반 lock 해제
  - Redis 장애 시 메모리 또는 단일 Upbit 호출 fallback
- 공통 성공/오류 envelope, camelCase 직렬화, 제한된 CORS 정책

## 기술 스택

| 영역 | 기술 |
| --- | --- |
| Language | Python 3.14 (Docker 이미지 기준) |
| Web | FastAPI 0.128, Uvicorn 0.40 |
| Validation / Settings | Pydantic, pydantic-settings |
| HTTP Client | HTTPX |
| Authentication | Supabase Auth, PyJWT (`crypto`) |
| Database | Supabase PostgreSQL / PostgREST / RLS |
| Cache / Lock | Redis 8, redis-py asyncio |
| Market Data | Upbit 공개 Quotation REST API |
| Test | pytest, pytest-asyncio, pytest-cov |
| Quality | Ruff, mypy, pre-commit |
| Container | Docker multi-stage build |

런타임 패키지는 `requirements.txt`, 개발 및 테스트 패키지는
`requirements-dev.txt`에서 관리합니다. 별도의 `pyproject.toml`은 없습니다.

## 시작하기

### 사전 요구 사항

- Python 3.14 권장
  - 저장소가 Python 버전을 별도 설정 파일로 고정하지는 않지만 Docker 이미지는
    Python 3.14를 사용합니다.
- Redis
- Supabase 프로젝트
  - Auth 사용자 및 비대칭 JWT 서명 키(ES256 또는 RS256)
  - `public.watchlist` 테이블과 사용자별 RLS 정책
- Upbit 공개 API에 접근 가능한 네트워크

재현 가능한 Supabase schema/RLS migration은
`supabase/migrations/20260805000000_create_watchlist.sql`에 포함되어 있습니다.
적용 전 대상 프로젝트와 현재 schema를 확인해야 합니다.

| 컬럼 | 기대 형식 및 제약 |
| --- | --- |
| `id` | `bigint`, PK, `GENERATED BY DEFAULT AS IDENTITY` |
| `user_id` | `uuid`, NOT NULL, `auth.users(id)` FK (`ON DELETE CASCADE`) |
| `market_code` | `varchar(20)`, NOT NULL, 정규화된 `KRW-*` 코드 |
| `korean_name` | `varchar(100)`, NOT NULL |
| `english_name` | `varchar(100)`, NOT NULL |
| `created_at` | `timestamptz`, NOT NULL, `DEFAULT now()` |

애플리케이션은 `(user_id, market_code)` 중복이 PostgreSQL UNIQUE 제약으로도
보장된다고 가정합니다. SELECT, INSERT 및 DELETE에는
`auth.uid() = user_id`를 적용하는 RLS 정책이 필요합니다.

### 환경변수

안전한 예시 파일을 복사한 뒤 로컬 값으로 설정합니다.

```bash
cp .env.example .env
```

실제 `.env`와 사용자 access token은 Git에 커밋하지 마세요.

| 변수 | 설명 | 기본값/비고 |
| --- | --- | --- |
| `APP_ENV` | 실행 환경 식별자 | `development` |
| `SUPABASE_URL` | Supabase 프로젝트 URL | 보호 API의 DB 접근에 필요 |
| `SUPABASE_ANON_KEY` | Supabase anon/publishable key | service role 사용 금지 |
| `SUPABASE_JWKS_URL` | JWT 공개키 endpoint | `<SUPABASE_URL>/auth/v1/.well-known/jwks.json` |
| `SUPABASE_ISSUER` | JWT issuer | `<SUPABASE_URL>/auth/v1` |
| `SUPABASE_AUDIENCE` | JWT audience | `authenticated` |
| `REDIS_URL` | Redis 연결 URL | 비어 있으면 `redis://localhost:6379/0` |
| `REDIS_TIMEOUT_SECONDS` | Redis 연결/명령 timeout | `2` |
| `UPBIT_BASE_URL` | Upbit API base URL | `https://api.upbit.com` |
| `UPBIT_TIMEOUT_SECONDS` | Upbit 단일 요청 timeout | `5` |
| `UPBIT_MAX_RETRIES` | Upbit 최대 재시도 횟수 | `2` |
| `CORS_ALLOWED_ORIGINS` | 허용 origin의 쉼표 구분 목록 | `http://localhost:5173` |

`SUPABASE_URL`, `SUPABASE_JWKS_URL`, `SUPABASE_ISSUER`는 모두 같은 프로젝트를
가리켜야 합니다. 사용자 access token은 서버 설정에 저장하지 않고 각 요청의
`Authorization` 헤더로 전달합니다.

## 실행 및 사용법

### 로컬 또는 devcontainer 실행

Redis를 먼저 실행한 뒤 다음 명령으로 API 서버를 시작합니다.

```bash
python -m uvicorn app.main:app \
  --reload \
  --host 0.0.0.0 \
  --port 8000
```

`--host 0.0.0.0`은 Dev Container port forwarding과 Render Web Service가
프로세스에 접근하기 위해 필요합니다. 로컬 프론트엔드 Origin은
`http://localhost:5173`이고 API base URL은 `http://localhost:8000/api`입니다.

서버 상태와 OpenAPI 문서는 다음 주소에서 확인할 수 있습니다.

- Health: <http://127.0.0.1:8000/api/health>
- Swagger UI: <http://127.0.0.1:8000/docs>
- OpenAPI JSON: <http://127.0.0.1:8000/openapi.json>

```bash
curl http://127.0.0.1:8000/api/health
```

```json
{
  "data": {
    "status": "ok"
  },
  "meta": null
}
```

### Docker 실행

Dockerfile 이름이 소문자 `dockerfile`이므로 `-f` 옵션을 사용합니다.

```bash
docker build -f dockerfile -t watchup-server .
docker run --rm \
  --env-file .env \
  -p 8000:8000 \
  watchup-server
```

컨테이너에서 별도 Redis를 사용한다면 `REDIS_URL`은 컨테이너 내부
`localhost`가 아니라 해당 Redis가 접근 가능한 주소여야 합니다.

### 인증

`GET /api/health`를 제외한 API는 Supabase 로그인으로 발급받은 실제
`access_token`이 필요합니다.

```http
Authorization: Bearer <SUPABASE_ACCESS_TOKEN>
```

anon/publishable key 또는 refresh token을 사용자 access token 대신 보내면
인증되지 않습니다.

### API 목록

| Method | Endpoint | 인증 | 설명 |
| --- | --- | --- | --- |
| `GET` | `/api/health` | 불필요 | 애플리케이션 health check |
| `GET` | `/api/coins/search?query={query}` | 필요 | KRW 코인 검색 |
| `GET` | `/api/coins/{marketCode}/chart` | 필요 | 30일 일봉 종가 조회 |
| `POST` | `/api/watchlist` | 필요 | 관심 코인 등록 |
| `GET` | `/api/watchlist` | 필요 | 관심목록과 현재가 조회 |
| `DELETE` | `/api/watchlist/{id}` | 필요 | 관심 코인 삭제 |

#### 코인 검색

```bash
curl -G "http://127.0.0.1:8000/api/coins/search" \
  -H "Authorization: Bearer <SUPABASE_ACCESS_TOKEN>" \
  --data-urlencode "query=비트코인"
```

```json
{
  "data": [
    {
      "marketCode": "KRW-BTC",
      "koreanName": "비트코인",
      "englishName": "Bitcoin",
      "status": "ACTIVE"
    }
  ],
  "meta": {
    "count": 1
  }
}
```

#### 관심 코인 등록

등록 요청에는 `marketCode`만 전달합니다. 사용자 ID와 코인명은 서버가 검증된
JWT 및 마켓 목록에서 결정합니다.

```bash
curl -X POST "http://127.0.0.1:8000/api/watchlist" \
  -H "Authorization: Bearer <SUPABASE_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"marketCode":"KRW-BTC"}'
```

성공 상태는 `201 Created`입니다.

```json
{
  "data": {
    "id": 1,
    "marketCode": "KRW-BTC",
    "koreanName": "비트코인",
    "englishName": "Bitcoin",
    "createdAt": "2026-07-29T00:00:00Z"
  },
  "meta": null
}
```

#### 관심목록과 현재가 조회

```bash
curl "http://127.0.0.1:8000/api/watchlist" \
  -H "Authorization: Bearer <SUPABASE_ACCESS_TOKEN>"
```

```json
{
  "data": [
    {
      "id": 1,
      "marketCode": "KRW-BTC",
      "koreanName": "비트코인",
      "englishName": "Bitcoin",
      "symbol": "BTC",
      "currentPrice": 120000000,
      "signedChangeRate": 1.25,
      "status": "ACTIVE",
      "isStale": false,
      "createdAt": "2026-07-29T00:00:00Z"
    }
  ],
  "meta": {
    "count": 1
  }
}
```

`currentPrice`와 `signedChangeRate`는 Upbit 응답을 기반으로 하므로 위 숫자는
응답 구조를 설명하기 위한 예시입니다. 실시간 값을 의미하지 않습니다.

#### 30일 일봉 차트

      {
        "date": "2026-07-28",

### 응답 계약

단일 성공 응답:

```json
{
  "data": {},
  "meta": null
}
```

목록 성공 응답:

```json
{
  "data": [],
  "meta": {
    "count": 0
  }
}
```

오류 응답:

```json
{
  "error": {
    "code": "INVALID_REQUEST",
    "message": "요청값이 올바르지 않습니다.",
    "details": null
  }
}
```

대표 오류 코드는 `AUTH_REQUIRED`, `AUTH_TOKEN_EXPIRED`,
`INVALID_MARKET_CODE`, `WATCHLIST_DUPLICATED`, `WATCHLIST_LIMIT_EXCEEDED`,
`UPBIT_UNAVAILABLE`, `UPBIT_RATE_LIMITED`, `UPBIT_TEMPORARILY_BLOCKED`,
`CACHE_REFRESH_IN_PROGRESS`, `INTERNAL_SERVER_ERROR`입니다.

## 캐시 정책

| 데이터 | Fresh key | Fresh TTL | Stale key | Stale TTL |
| --- | --- | ---: | --- | ---: |
| 마켓 목록 | `market:list` | 24시간 | 프로세스 메모리 snapshot | 프로세스 수명 |
| 현재가 | `price:{market_code}` | 5초 | `stale:price:{market_code}` | 1시간 |
| 일봉 차트 | `chart:{market_code}:1d` | 5분 | `stale:chart:{market_code}:1d` | 24시간 |

마켓 목록과 ticker 갱신은 Redis `SET NX EX` lock을 사용합니다. lock을 획득하지
못한 요청은 100ms 간격으로 최대 5회 캐시를 재확인합니다.

## 테스트와 코드 품질

기본 테스트는 실제 Redis, Upbit 또는 Supabase에 의존하지 않고 fake 및 mock
transport를 사용합니다. 현재 테스트 suite에는 인증, 공통 응답, CORS, Redis,
Upbit 재시도, 마켓 검색, 관심목록, ticker, 차트에 대한 테스트가 포함되어
있습니다.

```bash
python -m pytest -q
python -m ruff check app tests main.py
python -m ruff format --check app tests main.py
python -m mypy app
python -c "from app.main import app; print('application import: OK')"
python -m pip check
```

실제 Supabase RLS, Redis 연결 및 Upbit 응답에 대한 통합 검증은 별도의 개발
환경에서 수행해야 합니다.

## 기여 방법

1. 작업 전 현재 테스트와 Git 상태를 확인합니다.
2. 목적별 branch를 생성합니다.
3. 변경 범위에 맞는 테스트를 추가하거나 갱신합니다.
4. 전체 테스트, Ruff, format, mypy를 실행합니다.
5. 변경 내용, API/DB/캐시 영향, 실행한 검증 결과를 Pull Request에 작성합니다.

기여 시 다음 원칙을 지켜주세요.

- 실제 `.env`, JWT, refresh token, Redis password 또는 service role key를
  커밋하지 않습니다.
- 공개 REST 필드는 camelCase, Python 및 DB 내부 필드는 snake_case를 유지합니다.
- 일반 사용자 요청에 Supabase service role을 사용하거나 RLS를 우회하지 않습니다.
- 외부 API, Redis 및 Supabase 테스트는 fake/mock을 사용해 재현 가능하게 만듭니다.
- 관련 없는 리팩터링이나 대규모 포맷 변경을 기능 변경과 섞지 않습니다.
